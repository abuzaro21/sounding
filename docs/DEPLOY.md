# Deploy

## Local

```bash
npm ci
npm run db:up          # PostgreSQL 16 in Docker on 127.0.0.1:55432, app role NOSUPERUSER NOBYPASSRLS
npm run build
DATABASE_URL=postgres://app:app@127.0.0.1:55432/sim PORT=3100 npm start
```

Or the production image: `bash scripts/docker-smoke.sh` builds it, runs it against a throwaway PostgreSQL on a private Docker network and drives one full gate cycle over HTTP (`scripts/live-check.ts`, 18 checks).

## Render (free tier)

`render.yaml` is a Blueprint for one free Docker web service and one free PostgreSQL, with internal connections only (`ipAllowList: []`).

| Variable | Value |
|---|---|
| `NODE_ENV` | `production` (refuses relaxed limits) |
| `TRUST_PROXY_HOPS` | `3`. Render's edge adds the client plus two proxy hops; with 1, per-address limits do not hold |
| `SND_SECRET` | generated by Render |
| `DATABASE_URL` | the database's **internal** connection string |

Steps:

1. Use a Render workspace that holds **no other application's resources**. Render allows one free PostgreSQL per workspace, so SOUNDING needs its own. It must not reuse or modify any existing service, database or workspace.
2. Create the Blueprint from `render.yaml`, review the plan (free web service and free database only), then approve it.
3. The app migrates on start, as the database's single user (accepted risk: [ADR-007](ARCHITECTURE-DECISIONS.md)).
4. Verify: `node scripts/live-check.ts https://<service>.onrender.com`. It must report every check passed, including `rls_enforced: true` from `/healthz`.
5. `autoDeploy` is off. Redeploy deliberately after a push.

The free web service sleeps when idle; the first request after a sleep takes about a minute.

## Database continuity

A free Render PostgreSQL expires 30 days after creation and is deleted 14 days later. Every record in it is synthetic and disposable: visitors' workspaces live at most 24 h. Nothing needs to be migrated.

Before the expiry date:

1. Owner confirms deletion of the expiring SOUNDING database (and only that one).
2. Create a new free database in the same workspace.
3. Set the service's `DATABASE_URL` to its internal URL and redeploy; the app migrates the empty database on start.
4. Re-run `live-check` and record the new expiry here.

The demo is down between steps 1 and 3. That is the accepted cost of a free tier with one database per workspace.
